# apple/AGENTS.md

The iPhone, iPad and Apple TV apps and the `Kit` Swift package they share.
Read the root [AGENTS.md](../AGENTS.md) first. [README.md](README.md) has the
commands, the layout, the launch arguments and the code conventions (thin
views over `@Observable` models in `WMMFeatures`, services from the
environment, shared wording, Swift 6, Swift Testing); follow it. The plan and
its Status section are [PLAN-IOS.md](../PLAN-IOS.md); the screens follow
`design/mockups/ios/`, `ipad-revised/` ([PLAN-TABLETS.md](../PLAN-TABLETS.md))
and `apple-tv/`; `ipad/` keeps the earlier iPad designs for reference.

## Before handing work back

From the repository root:

| Changed | Run |
|---|---|
| Anything in `Kit/` | `make apple-test` (seconds, no simulator) |
| The iPhone or iPad app, or anything UIKit | `make apple-test-sim` |
| The Apple TV app | `make apple-tv-test-sim` |
| Sign-in, browsing or playback end to end | `make apple-e2e` against a fixture or throwaway server |
| The API (after `make gen-api`) | `make apple-api`, then `make apple-test` |

A screen change is also looked at on a simulator, on the fakes and against a
server, and on iPad in both a regular and a compact width.

## Rules for agents

- **Change `project.yml`, never the Xcode project.** `WatchMyMedia.xcodeproj`
  and `App/Info.plist` are generated by `make apple-gen` and not committed.
  The app and test folders are synced folders, so a new or removed file
  needs no regenerate; a change to `project.yml` does. A project generated
  before synced folders (one that lists each Swift file) misses new files
  until it is regenerated once.
- **The Swift client is generated** into `Kit/Sources/WMMAPI/Generated` by
  `make apple-api` and committed. It holds only the operations listed under
  `filter.operations` in `Kit/Sources/WMMAPI/openapi-generator-config.yaml`:
  add an operation there when an app starts calling it.
  `scripts/openapi-for-swift.py` adapts the document first.
  `scripts/open-response-enums.py` then opens response-reachable string enums;
  keep request-only enums strict and filter/reject unsupported domain states.
- **Google Cast** lives in the SDK-independent `WMMCast` Kit target, with
  the Google SDK bridge only in `App/Cast/`. Keep tvOS and macOS Kit tests free
  of that binary dependency, mirror the shared Cast protocol, and use the fake
  transport for automated tests. A real chooser/cast still needs explicit
  authorization under the root rules.
- **Older servers.** The generated client rejects a reply missing a required
  field, which is why new server reply fields must be optional (root file).
  Gate features on what the server offers, refreshed at launch, on
  foreground and when the event stream reconnects, without raising the
  app's minimum: `server.features.rows` (or `ServerFeatures(apiLevel:)`
  for a level held alone), never `apiLevel >= N`. A new level is one line
  in `ServerFeatures.Level` and a property named as Android's
  `ServerFeatures` names it, pinned in `ServerFeaturesTests` against the
  comment above `APILevel` in `server/internal/api/system.go`. The fakes
  still set a level by number (`ServerFeatures.Level.liveTV`).
- **Models, not views, decide.** Put state and rules in a `WMMFeatures` model
  and test it in `Kit/Tests/WMMFeaturesTests` against the fakes with
  `FakeLatency.duration = .zero`. Formatting goes in a `WMMModel` helper with a
  test, worded as the Android app words it.
- **Kit tests don't wait on the real clock.** A busy runner can leave the main
  actor hundreds of milliseconds behind, so a fixed `Task.sleep` before an
  assertion fails now and then. Give the model or fake a `sleep` (and `now`)
  and move a `ManualTime` (`PlayerTestSupport.swift`), as `PlayerHarness` and
  `FakePlaybackController(sleep:)` do (in `WMMDataTests`, the event
  stream's backoff and linger take `DataTuning.eventSleep`, which
  `ManualSleeps` ends), or wait for the state with `eventually { … }`.
  `FakeLatency` covers the fake repositories, not the fake player's own
  timing. `swift test --maximum-repetitions` repeats one test at a
  time, which doesn't load the main actor; to check a fix, run several copies
  of the whole test bundle at once.
- **iPhone and Apple TV share no files.** What both need goes in the Kit
  (README explains why `TV/` is separate from `App/`).
- **Settings' words and saving are the Kit's** (README, Settings). A page
  draws `SettingsWords`, `settingsHub`, `FlowStep` and the models' lines, and
  never words a setting itself; a control kept on the server reads its
  `SaveState` (`SettingsModel.saveState(_:)`, `LiveExtrasStore.leadSave`)
  rather than a page-wide error. A new such control gets a `SettingKey`, a
  Saved line that says what the change did and a failed line that names
  what it is still, with a test that moves the save's sleep.
- **Notifications have one delegate**, `NotificationRouter`
  (`App/Shell/NotificationRouter.swift`): it hands each category to its
  owner (`LiveReminderNotifier`, `NewEpisodeNotifier`) and registers every
  category at once, since `setNotificationCategories` replaces them all. A
  new kind of notification gets its own category, a case in the Kit's
  `NotificationOwner`, and its owner; a tap opens only a link the app
  published for the server signed in.
- **A 401 that isn't a lost sign-in** (a wrong current password) needs its
  operation in `ServerAPI.credentialOperations`, or the 401 signs the device
  out: `changePassword` is there.
- **The Top Shelf extension links only `WMMTopShelf`** and only reads the
  App Group (README, Top Shelf). Nothing the app writes there may name a
  server address, an image URL, a token or the person: add a field to the
  snapshot only through `TopShelfRules`, with a case in
  `TopShelfPublisherTests`' no-address test. `make apple-tv-build-release`
  fails if the extension picks up another Kit module. A link the shelf
  publishes goes through `DeepLink.url(publishedFor:source:)`. Code the
  extension runs must not use a required-reason API (file dates,
  UserDefaults) unless `TopShelf/PrivacyInfo.xcprivacy` declares it.
- **The iPhone Duo** (PLAN-IPHONE-DUO.md). Its inner screen reports a
  regular width held either way (951 × 669, 669 × 951) and its outer screen
  a compact one (466 × 678), so `isWide` already picks the right screens;
  decide a layout by the size class or the view's own width, never by
  `userInterfaceIdiom` (which stays for words: "This iPhone"). In apps iOS
  puts the tab bar in a vertical bar about 84 pt wide down one edge, as a
  safe area inset on that edge only, so a wide inner screen leaves 867 pt.
  The hinge reaches the screens as `\.foldPosture` (`readsFoldPosture()` at
  the root; `.tabletop` or `.book`, the fold through the middle of the
  window). iOS 27.1 APIs (`UIHingeInteraction`, `verticalBarEdge`) sit
  behind `#if compiler(>=6.4.1)` as well as `#available`, because an older
  Xcode may build the app. CI and the release did, on Xcode 26.6, until
  they moved to `scripts/select-xcode.sh`'s Xcode, so 1.9.2 (v1.6.1)
  shipped without them.
  - Pages go side by side from `PadLayout.sideBySide` (860 pt, so the Duo
    held wide gets two panes and the 11-inch iPad in portrait, 834 pt,
    still stacks); `PadLayout.landscape` (1000 pt) is where a page's
    controls fit in one row. Sideways rows end with `stopsAtVerticalBar()`.
  - Players turn by the window, not the device (`PlayerWindow`: wide only
    when regular both ways, since a Pro Max turned is regular width). The
    inner screen ignores the app's orientation mask and refuses any request
    to turn ("The current windowing mode does not allow…"), and a turn the
    outer screen granted stays with the scene after unfolding, so
    `OrientationLock` puts the request back to every way once a phone's
    window has turned and leaves `AppDelegate`'s mask to hold it. The outer
    screen also refuses a turn while the player's cover is presenting, so
    the request is retried every 250 ms a few times.
  - A fold must never rebuild the video: the video view stays at one place
    in the view tree and the layout only frames and moves it
    (`PlayerArrangement`). The same goes for anything open across a fold: a
    question shown as an alert when wide and an action sheet when compact
    keeps the form it opened in, or the fold drops it.
  - Upright, the tab bar's bottom inset (83 pt) reads 0 inside a view that
    ignores the safe area; read it outside with `onGeometryChange`.
  - Simulator: the Duo needs the runtime
    `com.apple.CoreSimulator.SimRuntime.iOS-27-2-iPhone19-4` (plain
    `iOS-27-2` refuses the device type). `simctl io <id> screenshot` takes
    `--display=1` for the outer screen and `--display=3` for the inner one.
    The simulator panel's screenshots can lag an action behind on the Duo,
    so wait and use `simctl io` before tapping from one. Closing straight
    after opening can black out the inner screen while SpringBoard restarts;
    the app keeps running.
- **Layout traps.** On Apple TV a focused `.borderless` button lifts and
  enlarges any `Image` in its label, so put a small icon inside the `Text`
  (`Text("\(Image(systemName: …)) …")`). On iPad a `.presentationSizing(.fitted)`
  form sheet keeps the height it opened at, so open it once its content has
  loaded (`RequestSheet.presented`). On iOS 27 a `ForEach` of card rows (each a
  horizontal `ScrollView` of a `LazyHStack`) inside a `LazyVStack` draws the
  rows made ahead of the scroll with their headings but no cards: Home's
  arranged rows are a `VStack` (`HomeScreen.arrangedRows`). In a `List` in edit
  mode (the rows sheet's `.onMove`) a row's plain `Button` takes no taps: give
  it `.buttonStyle(.borderless)` or a style of its own.
  In a horizontal `ScrollView` with `.contentMargins` (Apple TV's rows,
  90 pt), three measures of "where" disagree (tvOS 27.2 simulator): a
  card's `frame(in: .scrollView(axis: .horizontal))` counts from the
  leading margin, not the screen's edge; `ScrollGeometry.contentOffset` is
  minus the margin at the row's start; and `ScrollPosition.scrollTo(x:)`
  counts from the row's start. `RowStartScrolling`
  (`TV/Components/RowStart.swift`) adds the margin to the offset before
  scrolling to a card; without it the row scrolled a card too far.
  Inside the player's full-screen cover a `GeometryReader` that ignores the
  safe area reports zero `safeAreaInsets` (iOS 27.2 simulator): `PlayerShell`
  measures them between a reader that keeps the safe area and one that
  doesn't. A view's `.onChange(of: scenePhase)` under the tab view was not
  seen to report `.background` before the app was ended, so state that must
  survive eviction is saved when it changes (`PlaceKeeping`).
- **Home's screens** (PLAN-HOME.md §7; `HomeScreen.swift` on both apps): a
  vertical `ScrollView` with `.scrollTargetBehavior(.paging)`, each screen
  `.containerRelativeFrame(.vertical)`. A horizontal card row inside a screen
  takes all the height the panel leaves unless it has
  `.fixedSize(horizontal: false, vertical: true)`. On iPad the scroll view
  must `.ignoresSafeArea(edges: .bottom)`: paging steps by the scroll view's
  bounds while the frame leaves out the inset, so the next screen's top shows
  under the next-row line otherwise. On Apple TV focus moving into a row lands
  on the card nearest the way it came, whatever `defaultFocus` says, so
  `ShelfRow` and the Live TV rows move it to the remembered or first card when
  focus enters (`old == nil` in `onChange(of: focused)`); a container's
  `.focused($page, equals: n)` reports which screen holds focus and, set,
  moves focus into that screen (Back to the top, Menu). The Siri Remote in the
  simulator tool has no Menu key: `TVUITests/HomeScreensTests.swift` checks
  Menu with `XCUIRemote`. On Apple TV each screen is identified by what it
  shows (`HomePage`), not its place, and a row's screen (`HomeRowScreen`)
  holds its own focused card: a row appearing above keeps the others' cards,
  and moving along a row redraws that screen alone. Selecting another tab
  from code (a row's See all) sends focus to the tab bar first, which
  scrolls Home to its first screen, and coming back to Home leaves focus in
  the tab bar: Home puts a row back itself after Menu (`seeAllLeft`,
  `Navigator.exitsToHome`; `TVUITests/SeeAllTests.swift`).
- **Dialogs and focus.**
  - iOS 27's Back is a bare chevron. Hiding it for a labelled Back of your
    own turns off the edge swipe, and on iPad a leading toolbar item goes into
    an overflow menu beside the tab bar, so pages keep the system's Back.
  - On iPhone a `.confirmationDialog` grows from the view it is attached to, so
    attach it to the button that asked (the ⋯ menu), not the page.
  - An alert or dialog sets its `isPresented` binding to false before a
    button's `Task` runs, so pass the presented item into the action rather
    than reading the model's copy (`ShowPageModel.confirm(_:)`).
  - On Apple TV, Up or Down only reaches a `.focusSection()` whose frame lies
    across the move, so give a short row of buttons `.frame(maxWidth: .infinity)`.
    Down from the tab bar lands on the button under the focused tab, not the
    first in the row: a test moves left or right from there
    (`TVUITests/TrailerTests.swift`).
  - On the show page (`TV/Screens/Detail/ShowScreen.swift`) focus moving
    along the row changes the episode on top, and focus reaching a tab
    chooses its season. Focus coming into the row or the tabs from above or
    below lands on whatever is nearest, so the page moves it to the card on
    top (or the chosen tab) before following it; otherwise coming up from the
    row would choose the season over the card. Measured with `_printChanges`
    on tvOS 27: the view that owns a `@FocusState` is redrawn on every focus
    move whatever its body reads, a container that takes a closure under it
    (`TabPage`) then rebuilds its content, and an `.equatable()` view's `==`
    isn't asked for its first several updates; so what changes with each
    move (the episode on top) is read only in views of its own (`Separately`).
    Building `TabPage`'s content once, in its `init`, saves nothing: the
    owner's body runs on each move and would build it there instead
    (measured 2026-11-13: one `TabPage` content build per owner redraw, none
    besides), and the model reads in the content would then redraw the owner
    rather than `TabPage` alone.
  - Apple TV's Settings (`TV/Screens/Settings/SettingsScreen.swift`, the
    groups beside their page) moves focus the focus engine puts elsewhere:
    Right from the list lands on the row level with the group, so it goes
    to the page's remembered row; Left from a page lands on whichever group
    is level with the row, which would change the page, so it goes to the
    page's own group; and focus coming back from nil goes to where it was.
    The view's `@FocusState` is nil while the top bar has focus and while a
    `Menu`'s choices, a full-screen cover or a question is up, so "from nil"
    covers all of them. A press made before the move lands goes from where
    focus was, so a test waits for focus after each press. `MainTabs`
    leaves Menu at Settings' root to the system (the top bar); the page has
    its own `onExitCommand` back to the list.
  - In a SwiftUI `Menu` on Apple TV a `Label { Text; Text } icon:` item
    drops its second `Text`, so a ticked choice lost its line. A `Toggle`
    per choice keeps the title and the line and is ticked when on
    (Settings' `menuRow`). The menu opens with focus on its first choice,
    not the ticked one. XCUI sees each toggle as an `Other` inside a cell,
    `isSelected` when ticked. tvOS 27 labels it "title, line" by itself
    and drops its identifier; tvOS 26.5 keeps the identifier but reads out
    the title alone, so each toggle sets its `accessibilityLabel` to both.
    Find a choice by that label (`TVUITests/SettingsTests.swift`).
    A `Menu`'s own label isn't read out either, so a row that is a `Menu`
    sets its `accessibilityLabel` and `accessibilityValue`.
  - On Apple TV, when a focused button's content is replaced (sign-in's
    "Sign in with a password instead"), focus goes to the new content's
    `defaultFocus` only if what was replaced was built in the same body.
    With the pairing pieces moved into views of their own, nothing had
    focus after the switch (tvOS 27.2 simulator, `BusyFocusTests`), so the
    pieces sign-in and Switch server share are `@ViewBuilder` functions
    (`pairingCodeArea(_:)` in `TV/Screens/SignIn/SignInScreen.swift`).
    Even built in the same body, Switch server's form was left with nothing
    focused on CI's tvOS 26.5 simulator (never on this Mac's, loaded or
    not), so it moves focus itself when the way in changes
    (`onChange(of: signIn.codeSignIn)` in `SwitchServerScreen.swift`).
  - On tvOS 26.5 focus asked through a `@FocusState` of a view a lazy grid
    hasn't drawn yet is dropped without a word, and no `onChange` follows
    (the library grid's Menu from the letter index, once a letter's jump
    had scrolled the poster away; on a loaded simulator, and on CI). On
    tvOS 27.2, on CI's runner, the same request sent focus to another
    poster, which the index took for a swipe left. The grid's `focusItem`
    (`TV/Screens/Library/LibraryScreen.swift`) scrolls the poster in, asks
    once the grid has drawn it (its `onAppear`), and asks again until focus
    lands, and `focusMoved` lets a move from the index to another poster
    pass while it asks. Ask that way wherever focus goes to something that
    may be off screen. On this Mac neither shows: CI's slower runner does.
  - On Apple TV a focused button that becomes disabled keeps focus, dimmed,
    until the remote moves it (tvOS 27 simulator: Sign in, Mark watched, Move
    up at the top; `TVUITests/BusyFocusTests.swift`), so a button may disable
    itself while it works.
  - On Apple TV Play/Pause goes to the focused view's `.onPlayPauseCommand`
    and nowhere else: a card plays with `playPauseCard(_:select:)`, whose
    rule is `CardPlayPause` in the Kit (a show's card opens, as Select does),
    and a new card needs it too (`TVUITests/PlayPauseCardTests.swift`).
  - A note pill's timer is cancelled while a page settles in after Back, so
    clear the note only when the sleep finished (`MessagePill`).
  - On iPad the toolbar beside the tab bar holds little: a third trailing
    item sends the rest into a ⋯ menu. Put a page's own buttons in its title
    row (the Live TV guide's search, Reminders and Guide/Channels switch).
- **Settings** (README, Settings; PLAN-APPLE-SETTINGS.md). A task with steps
  is a sheet in `TaskFrame`, presented from `SettingsTasks` in
  `SettingsScreen.swift` so both widths share it, with its model kept in
  `AppFlow` so a resized iPad window keeps the step. `.linkTV` in the
  Settings tab's path is that sheet, never a pushed page: `MainTabView`
  leaves it out of the stack's path (`[Route].pushed`) and keeps it when the
  stack changes the path. A finished Switch server shows its last step until
  Done (`AppFlow.serverSwitchDone`); only then does `RootView` rebuild the
  tabs. A sheet that must ask before a swipe throws away what was typed uses
  `asksBeforeDismissing`: `interactiveDismissDisabled` alone refuses the swipe
  without saying so, and the helper hears UIKit's attempt through a proxy in
  front of SwiftUI's own presentation delegate. A choice from a row's menu is
  a `Toggle` per choice in a `Menu`: it ticks the chosen one and a second
  `Text` is its line. A page's two columns hold groups in another order than
  the phone's single column, so a page gives each its own (`SettingsAdaptive`).
  The words, saving states, steps and dialogs are the Kit's (`SettingsWords`,
  `SaveState`, `FlowStep`, `ConfirmWords`): a view draws a control's
  `saveState` as its row's line with `rowLine(rest:)` and disables only that
  control while it saves, and a new sentence goes into the Kit, not the view.
  To see or test a refusal on the fakes, launch a debug build with
  `-fakesSaveFails <part>` or `-fakesPasswordFails <status>`.
- **Accessibility identifiers.** An `.accessibilityIdentifier` on a container
  that isn't an element (a `VStack`, a `TimelineView`) is given to every
  child, over their own: add `.accessibilityElement(children: .contain)`
  first. A Button's identifier replaces those of the views in its label. On
  Apple TV a context menu's items are `Other` elements to XCUI, found by
  their label, not buttons. A SwiftUI `Menu` on Apple TV takes focus on an
  element inside it, so its own `hasFocus` stays false, and its items are
  cells with each item's identifier on a view inside: find what has focus
  (`hasFocus == true`) and compare frames (`TVUITests/FirstRunAndSubtitleTests.swift`).
  A poster card's Button still lists its title as a `StaticText` to XCUI
  (iOS 27.2), though the card ignores its children for VoiceOver, so a
  page's title also matches a card of it in a related row: tell pages
  apart by something only the page shows, as the show page's eyebrow
  (`UITests/RelatedTitlesTests.swift`).

## Simulators

Other sessions keep simulators booted. Don't use, erase or shut down one you
didn't start.

- A fresh install needs `xcrun simctl keychain <udid> reset` as well as
  `simctl uninstall`: the Keychain keeps the sign-in, on Apple TV too.
- The Top Shelf shows on the tvOS simulator above the app's icon when it is
  focused in the Home Screen's top row (a new simulator has only a few apps,
  so the app is there). Run the app on the fakes, then press Home with the
  remote (`XCUIRemote` in a UI test) and capture with `simctl io`. On tvOS 27.2
  `XCUIRemote`'s Up from the icon did not move focus into the shelf, so a
  focused card's title, the second section and Select or Play/Pause on a card
  need a hand on the Simulator or a device. `xcrun simctl get_app_container
  <udid> media.watchmy.client groups` finds the App Group's folder, with the
  snapshot as snapshot.json in its TopShelf folder. The Home Screen's order
  is the simulator's HeadBoard AppOrder.plist, under its data's Library.
- Make your own (`xcrun simctl create "WMM <name>" <device type> <runtime>`),
  pass its name (not its UDID) to make as `SIM=` or `TV_SIM=`, and delete it
  afterwards. A UDID matches no name, so the tests quietly run on the default
  iPhone Pro or Apple TV 4K, which other sessions use.
  `scripts/simulator.sh` resolves names to a UDID and falls back to the newest
  iPhone Pro or Apple TV when the named one is missing (as on CI's runners).
- `make apple-test-sim` runs the Kit's tests on the simulator: the
  `WatchMyMedia` scheme has no UI test target, so `UITests/` runs only
  through the `WatchMyMediaE2E` scheme, one class or test at a time with
  `-only-testing:WatchMyMediaUITests/<Class>` (README's trailer recipe;
  `-test-iterations 5 -run-tests-until-failure` repeats one).
- On iPhone the keyboard covers the tab bar: a UI test that taps a tab while
  a field has the keyboard up taps a key instead. Put the keyboard away
  first, wait for the tab's `isSelected`, and find a page's search field by
  its prompt, since another tab's may still be in the tree
  (`UITests/LiveExtrasTests.swift`). On iPad (iPadOS 27.2) the tabs beside
  the title are not in `app.tabBars`: find a tab as `app.buttons[name]`
  when the tab bar has none (`UITests/SeeAllTests.swift`).
- Builds for the simulator are signed ad hoc (`APPLE_SIM_SIGNING` in the
  Makefile). Without it the Keychain refuses the app and the sign-in does not
  survive a relaunch, so use the make targets or copy those flags.
- Nothing can tap a simulator from a script, so reach screens with launch
  arguments (`-fakes`, `-tab`, `-open watchmymedia://…`, the player's
  `-player…` arguments) and capture with `xcrun simctl io <udid> screenshot`.
  Screenshots can lag a frame: take another before acting on one. A
  Settings row says Saved for 4 s (`SaveStates.linger`), which a press with
  the simulator tool followed by its screenshot can outlast: capture with
  `xcrun simctl io` straight after the press, or read the row in a UI test.
- A UI test can't open the app from a notification on the Lock Screen or in
  Notification Center (iOS 27.2 simulator): the first tap opens the app's
  stack and the next opens nothing. With the app open, iOS shows the
  notification as a banner, and a tap on that reaches the app
  (`UITests/NewEpisodesTests.swift`).
- The Simulator (iOS 27.2) doesn't keep a `BGAppRefreshTaskRequest`: the
  submit is logged, then `_simulateLaunchForTaskWithIdentifier` from the
  debugger says no request has been scheduled. Check background refresh
  work on a device, and its logic in the Kit (`NewEpisodeChecker`).
- Run `make apple-e2e` against your own server copy on its own port
  (`E2E_SERVER=localhost:<port>`), not a fixture server another session runs.
- Typing into the in-app Safari (`SFSafariViewController`) arrives late and
  drops characters when fields change quickly: one field at a time, then
  check. XCUITest's `typeText` into a tvOS field drops characters the same
  way when the Mac is busy: type one character at a time.
- Building the apps with `xcodebuild` rewrites `Kit/Package.resolved` with
  Google Cast's pins: leave that change out of commits.
- YouTube's player (the movie trailer screen) needs the network. No video is
  known to refuse embedding reliably, so reach the refused screen with
  `-trailerError 150` in a debug build.
- On iOS 27 a `.confirmationDialog` is a popover from the view it is
  attached to, on iPhone as on iPad, and shows no `.cancel` button: tapping
  outside is the answer that keeps things. A test finds the dialog's buttons
  inside `app.popovers` (a row's own button can carry the same label) and
  keeps things with a tap on `app.otherElements["PopoverDismissRegion"]`
  (`UITests/SettingsTasksTests.swift`).
- `typeKey` drives a hardware keyboard on the iOS simulator (space, arrows,
  ⌘F: `UITests/KeyboardTests.swift`, on an iPad), but its Escape reached
  neither `onKeyPress`, a cancel action nor a `UIKeyCommand` on iPadOS 27.2:
  check Escape with a real keyboard.
- XCTest's own waits look late in the Apple TV UI tests (tvOS 27.2
  simulator): `waitForExistence`, `waitForNonExistence` and an
  `XCTNSPredicateExpectation` waited on with `XCTWaiter` first look about a
  second after they start, even when what they wait for is already there,
  and the expectation then looks only every 6 s. A wait after each remote
  press cost 1.3 s a press. The TV UI tests wait with
  `TVUITests/Waiting.swift` (`waitUntilExists`, `waitUntilGone`,
  `waitForFocus`, `wait(until:)`, `eventually`), which look at once and then
  every quarter second; use those. XCTest's late look also let each new
  screen settle before the next press, so `waitUntilExists` and
  `waitUntilGone` give it half a second; where a press needs focus
  somewhere, wait for that focus, and where an element stays in the tree
  under a pushed page (the grid's Sort by), wait for the page to go. In a
  loop that presses until focus reaches something, wait for focus to move
  after each press (`press(_:thenWaitForFocusToMove:)`), not for the target:
  a slow move is otherwise pressed twice, or each step on the way waits out
  the timeout. `snapshot()` retries for 2 s on a missing element, so ask
  `exists` first (`lookedAt`). A look at the screen once took 8 s on a busy
  simulator, so read something shown briefly in the look that finds it
  (`wait(until:)` reads one snapshot) and keep it up long enough for a whole
  look (`-liveBannerSeconds 15` for the reminder banner).
- XCUITest's Siri Remote has no touch-surface swipe, and Right while paused
  skips 10 s, so AVKit's own scrubbing (and the thumbnails it draws from an
  I-frame playlist) can't be driven from a test; check it by hand.
- The fakes have backdrops drawn in code (`FakeBackdrops`, six fictional
  scenes by title) but no posters, and the fixture has no artwork at all, so
  poster-driven layout bugs don't show in tests. To check them, make the fakes
  return poster images on a throwaway simulator and revert that before
  committing.
- The fixture's titles are made up and unmatched, so it has no movie or
  episode pages, and no Download button. On your own scratch copy of the
  database, give a file a page by hand: insert a `movies` row and set the
  file's `movie_id`, `match_status = 'matched'` and `match_locked = 1`.
- A download's HLS package is named by the system from its title,
  percent-encoded (`Harbor%20Lights_….movpkg` is the folder's real name):
  keep the `relativePath` it gives as it is; decoding it misses the folder.
- On this Mac some simulator runtimes are intermittently unavailable to
  `xcodebuild` even when `simctl` lists them; pick another runtime rather than
  debugging the project.

## Releases

The `ios` job in `release.yml` archives on every `v*` tag and uploads to
TestFlight once the App Store Connect key secrets are set; until then it
builds for the simulator. It and CI's `apple` and `apple-tv` jobs build with
the Xcode `scripts/select-xcode.sh` names, on GitHub's `xcode-27` image: App
Store Connect flags uploads made with the iOS 26 SDK (ITMS-90725) and from
April 2027 refuses them. Raise the version there, never in one workflow alone
(`deploy/ci/security_test.py` checks). `make apple-archive` and
`make apple-upload` sign with the accounts on this Mac and upload: run them
only when the user asks.
When the user archives in Xcode, run `make apple-gen VERSION=vX.Y.Z` first, or
the archive is the placeholder 1.0 (1) in `project.yml`.
The Apple TV app can't be archived in Xcode while the team has no Apple TV
registered ("Your team has no devices from which to generate a provisioning
profile"): `make apple-tv-archive` archives it unsigned, and
`make apple-tv-upload` signs it at export with Apple Distribution and an App
Store profile, which needs no device. Run the upload only when the user asks.
Google ships `GoogleCast.framework` without a dSYM, so the iPhone target's
archive-only "Make GoogleCast's dSYM" step makes one with `dsymutil`. Without
it, an upload warns "The archive did not include a dSYM for the
GoogleCast.framework" but still succeeds.
App Store Connect declarations, agreements and keys are the user's.
App Store text (description, promotional text, What's New, screenshot
captions) names only Apple devices and the web app: no Android, Google TV or
Google Play. App Review rejected iPhone 1.5.5 under Guideline 2.3.10 for
"the web app, Android, Google TV and your iPhone and iPad" in the description.
