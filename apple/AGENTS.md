# apple/AGENTS.md

The iPhone, iPad and Apple TV apps and the `Kit` Swift package they share.
Read the root [AGENTS.md](../AGENTS.md) first. [README.md](README.md) has the
commands, the layout, the launch arguments and the code conventions (thin
views over `@Observable` models in `WMMFeatures`, services from the
environment, shared wording, Swift 6, Swift Testing); follow it. The plan and
its Status section are [PLAN-IOS.md](../PLAN-IOS.md); the screens follow
`design/mockups/ios/`, `ipad-revised/` ([PLAN-TABLETS.md](../PLAN-TABLETS.md))
and `apple-tv/`; `ipad/` keeps the earlier iPad designs for reference.

## Before handing work back

From the repository root:

| Changed | Run |
|---|---|
| Anything in `Kit/` | `make apple-test` (seconds, no simulator) |
| The iPhone or iPad app, or anything UIKit | `make apple-test-sim` |
| The Apple TV app | `make apple-tv-test-sim` |
| Sign-in, browsing or playback end to end | `make apple-e2e` against a fixture or throwaway server |
| The API (after `make gen-api`) | `make apple-api`, then `make apple-test` |

A screen change is also looked at on a simulator, on the fakes and against a
server, and on iPad in both a regular and a compact width.

## Rules for agents

- **Change `project.yml`, never the Xcode project.** `WatchMyMedia.xcodeproj`
  and `App/Info.plist` are generated by `make apple-gen` and not committed.
  The app and test folders are synced folders, so a new or removed file
  needs no regenerate; a change to `project.yml` does. A project generated
  before synced folders (one that lists each Swift file) misses new files
  until it is regenerated once.
- **The Swift client is generated** into `Kit/Sources/WMMAPI/Generated` by
  `make apple-api` and committed. It holds only the operations listed under
  `filter.operations` in `Kit/Sources/WMMAPI/openapi-generator-config.yaml`:
  add an operation there when an app starts calling it.
  `scripts/openapi-for-swift.py` adapts the document first.
  `scripts/open-response-enums.py` then opens response-reachable string enums;
  keep request-only enums strict and filter/reject unsupported domain states.
- **Google Cast** lives in the SDK-independent `WMMCast` Kit target, with
  the Google SDK bridge only in `App/Cast/`. Keep tvOS and macOS Kit tests free
  of that binary dependency, mirror the shared Cast protocol, and use the fake
  transport for automated tests. A real chooser/cast still needs explicit
  authorization under the root rules.
- **Older servers.** The generated client rejects a reply missing a required
  field, which is why new server reply fields must be optional (root file).
  Gate features on the server's `apiLevel`, refreshed at launch and on
  foreground, without raising the app's minimum.
- **Models, not views, decide.** Put state and rules in a `WMMFeatures` model
  and test it in `Kit/Tests/WMMFeaturesTests` against the fakes with
  `FakeLatency.duration = .zero`. Formatting goes in a `WMMModel` helper with a
  test, worded as the Android app words it.
- **Kit tests don't wait on the real clock.** A busy runner can leave the main
  actor hundreds of milliseconds behind, so a fixed `Task.sleep` before an
  assertion fails now and then. Give the model or fake a `sleep` (and `now`)
  and move a `ManualTime` (`PlayerTestSupport.swift`), as `PlayerHarness` and
  `FakePlaybackController(sleep:)` do, or wait for the state with
  `eventually { … }`. `FakeLatency` covers the fake repositories, not the fake
  player's own timing. `swift test --maximum-repetitions` repeats one test at a
  time, which doesn't load the main actor; to check a fix, run several copies
  of the whole test bundle at once.
- **iPhone and Apple TV share no files.** What both need goes in the Kit
  (README explains why `TV/` is separate from `App/`).
- **Layout traps.** On Apple TV a focused `.borderless` button lifts and
  enlarges any `Image` in its label, so put a small icon inside the `Text`
  (`Text("\(Image(systemName: …)) …")`). On iPad a `.presentationSizing(.fitted)`
  form sheet keeps the height it opened at, so open it once its content has
  loaded (`RequestSheet.presented`). On iOS 27 a `ForEach` of card rows (each a
  horizontal `ScrollView` of a `LazyHStack`) inside a `LazyVStack` draws the
  rows made ahead of the scroll with their headings but no cards: Home's
  arranged rows are a `VStack` (`HomeScreen.arrangedRows`). In a `List` in edit
  mode (the rows sheet's `.onMove`) a row's plain `Button` takes no taps: give
  it `.buttonStyle(.borderless)` or a style of its own.
- **Home's screens** (PLAN-HOME.md §7; `HomeScreen.swift` on both apps): a
  vertical `ScrollView` with `.scrollTargetBehavior(.paging)`, each screen
  `.containerRelativeFrame(.vertical)`. A horizontal card row inside a screen
  takes all the height the panel leaves unless it has
  `.fixedSize(horizontal: false, vertical: true)`. On iPad the scroll view
  must `.ignoresSafeArea(edges: .bottom)`: paging steps by the scroll view's
  bounds while the frame leaves out the inset, so the next screen's top shows
  under the next-row line otherwise. On Apple TV focus moving into a row lands
  on the card nearest the way it came, whatever `defaultFocus` says, so
  `ShelfRow` and the Live TV rows move it to the remembered or first card when
  focus enters (`old == nil` in `onChange(of: focused)`); a container's
  `.focused($page, equals: n)` reports which screen holds focus and, set,
  moves focus into that screen (Back to the top, Menu). The Siri Remote in the
  simulator tool has no Menu key: `TVUITests/HomeScreensTests.swift` checks
  Menu with `XCUIRemote`.
- **Dialogs and focus.**
  - iOS 27's Back is a bare chevron. Hiding it for a labelled Back of your
    own turns off the edge swipe, and on iPad a leading toolbar item goes into
    an overflow menu beside the tab bar, so pages keep the system's Back.
  - On iPhone a `.confirmationDialog` grows from the view it is attached to, so
    attach it to the button that asked (the ⋯ menu), not the page.
  - An alert or dialog sets its `isPresented` binding to false before a
    button's `Task` runs, so pass the presented item into the action rather
    than reading the model's copy (`ShowPageModel.confirm(_:)`).
  - On Apple TV, Up or Down only reaches a `.focusSection()` whose frame lies
    across the move, so give a short row of buttons `.frame(maxWidth: .infinity)`.
    Down from the tab bar lands on the button under the focused tab, not the
    first in the row: a test moves left or right from there
    (`TVUITests/TrailerTests.swift`).
  - On the show page (`TV/Screens/Detail/ShowScreen.swift`) focus moving
    along the row changes the episode on top, and focus reaching a tab
    chooses its season. Focus coming into the row or the tabs from above or
    below lands on whatever is nearest, so the page moves it to the card on
    top (or the chosen tab) before following it; otherwise coming up from the
    row would choose the season over the card.
  - On Apple TV a focused button that becomes disabled keeps focus, dimmed,
    until the remote moves it (tvOS 27 simulator: Sign in, Mark watched, Move
    up at the top; `TVUITests/BusyFocusTests.swift`), so a button may disable
    itself while it works.
  - A note pill's timer is cancelled while a page settles in after Back, so
    clear the note only when the sleep finished (`MessagePill`).
  - On iPad the toolbar beside the tab bar holds little: a third trailing
    item sends the rest into a ⋯ menu. Put a page's own buttons in its title
    row (the Live TV guide's search, Reminders and Guide/Channels switch).
- **Accessibility identifiers.** An `.accessibilityIdentifier` on a container
  that isn't an element (a `VStack`, a `TimelineView`) is given to every
  child, over their own: add `.accessibilityElement(children: .contain)`
  first. A Button's identifier replaces those of the views in its label. On
  Apple TV a context menu's items are `Other` elements to XCUI, found by
  their label, not buttons. A SwiftUI `Menu` on Apple TV takes focus on an
  element inside it, so its own `hasFocus` stays false, and its items are
  cells with each item's identifier on a view inside: find what has focus
  (`hasFocus == true`) and compare frames (`TVUITests/FirstRunAndSubtitleTests.swift`).

## Simulators

Other sessions keep simulators booted. Don't use, erase or shut down one you
didn't start.

- A fresh install needs `xcrun simctl keychain <udid> reset` as well as
  `simctl uninstall`: the Keychain keeps the sign-in, on Apple TV too.
- Make your own (`xcrun simctl create "WMM <name>" <device type> <runtime>`),
  pass its name (not its UDID) to make as `SIM=` or `TV_SIM=`, and delete it
  afterwards. A UDID matches no name, so the tests quietly run on the default
  iPhone Pro or Apple TV 4K, which other sessions use.
  `scripts/simulator.sh` resolves names to a UDID and falls back to the newest
  iPhone Pro or Apple TV when the named one is missing (as on CI's runners).
- Builds for the simulator are signed ad hoc (`APPLE_SIM_SIGNING` in the
  Makefile). Without it the Keychain refuses the app and the sign-in does not
  survive a relaunch, so use the make targets or copy those flags.
- Nothing can tap a simulator from a script, so reach screens with launch
  arguments (`-fakes`, `-tab`, `-open watchmymedia://…`, the player's
  `-player…` arguments) and capture with `xcrun simctl io <udid> screenshot`.
  Screenshots can lag a frame: take another before acting on one.
- Run `make apple-e2e` against your own server copy on its own port
  (`E2E_SERVER=localhost:<port>`), not a fixture server another session runs.
- Typing into the in-app Safari (`SFSafariViewController`) arrives late and
  drops characters when fields change quickly: one field at a time, then
  check. XCUITest's `typeText` into a tvOS field drops characters the same
  way when the Mac is busy: type one character at a time.
- Building the apps with `xcodebuild` rewrites `Kit/Package.resolved` with
  Google Cast's pins: leave that change out of commits.
- YouTube's player (the movie trailer screen) needs the network. No video is
  known to refuse embedding reliably, so reach the refused screen with
  `-trailerError 150` in a debug build.
- XCUITest's Siri Remote has no touch-surface swipe, and Right while paused
  skips 10 s, so AVKit's own scrubbing (and the thumbnails it draws from an
  I-frame playlist) can't be driven from a test; check it by hand.
- The fakes have backdrops drawn in code (`FakeBackdrops`, six fictional
  scenes by title) but no posters, and the fixture has no artwork at all, so
  poster-driven layout bugs don't show in tests. To check them, make the fakes
  return poster images on a throwaway simulator and revert that before
  committing.
- The fixture's titles are made up and unmatched, so it has no movie or
  episode pages, and no Download button. On your own scratch copy of the
  database, give a file a page by hand: insert a `movies` row and set the
  file's `movie_id`, `match_status = 'matched'` and `match_locked = 1`.
- A download's HLS package is named by the system from its title,
  percent-encoded (`Harbor%20Lights_….movpkg` is the folder's real name):
  keep the `relativePath` it gives as it is; decoding it misses the folder.
- On this Mac some simulator runtimes are intermittently unavailable to
  `xcodebuild` even when `simctl` lists them; pick another runtime rather than
  debugging the project.

## Releases

The `ios` job in `release.yml` archives on every `v*` tag and uploads to
TestFlight once the App Store Connect key secrets are set; until then it
builds for the simulator. `make apple-archive` and `make apple-upload` sign
with the accounts on this Mac and upload: run them only when the user asks.
When the user archives in Xcode, run `make apple-gen VERSION=vX.Y.Z` first, or
the archive is the placeholder 1.0 (1) in `project.yml`.
The Apple TV app can't be archived in Xcode while the team has no Apple TV
registered ("Your team has no devices from which to generate a provisioning
profile"): `make apple-tv-archive` archives it unsigned, and
`make apple-tv-upload` signs it at export with Apple Distribution and an App
Store profile, which needs no device. Run the upload only when the user asks.
Google ships `GoogleCast.framework` without a dSYM, so the iPhone target's
archive-only "Make GoogleCast's dSYM" step makes one with `dsymutil`. Without
it, an upload warns "The archive did not include a dSYM for the
GoogleCast.framework" but still succeeds.
App Store Connect declarations, agreements and keys are the user's.
App Store text (description, promotional text, What's New, screenshot
captions) names only Apple devices and the web app: no Android, Google TV or
Google Play. App Review rejected iPhone 1.5.5 under Guideline 2.3.10 for
"the web app, Android, Google TV and your iPhone and iPad" in the description.
